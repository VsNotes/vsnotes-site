🤔 WHAT IS AGENTIC AI?
🤖The Agent says:

"Don't just answer me — go figure it out!"
A normal chatbot waits for you. An Agentic AI takes initiative — it searches the web, reads files, runs code, calls APIs, remembers past conversations, and loops until the job is done.

1
💬

Chatbot

You ask → It answers. One shot. No memory. No actions. Think: basic FAQ bot.

2
📚

RAG

You ask → It searches your docs → Answers. Smarter but still reactive. No loops.

3
⚡

Agent

You ask → It plans → Uses tools → Observes → Loops → Gets it done. Fully autonomous!

★
🤝

Multi-Agent

Teams of specialist agents working together. One researches, one writes, one checks. Like a real dev team!

🔄 THE REACT LOOP (CORE CONCEPT)
💡 What's ReAct?

Reasoning + Acting — the brain of every agent. The LLM thinks, picks a tool, runs it, sees the result, thinks again, and repeats until done. No human needed in the loop!

📦 What Each Library Does
  • LangChain — builds prompts, chains LLM calls, defines tools. The "scaffolding".
  • LangGraph — runs the stateful ReAct loop. Decides when to loop, when to stop.
  • OpenAI SDK — talks to GPT-4o. LangChain wraps this automatically.
  • FAISS — stores text as vectors. Lets the agent "remember" documents semantically.
  • FastAPI — wraps the agent as a web API so anyone can call it.

🤖 The 3 Levels of AI (Know Where You Are)

Level 1 — Chatbot: Input → LLM → Output. One shot. No memory.
Level 2 — RAG: Input → Search Docs → LLM → Output. Smarter but still single-shot.
Level 3 — Agent: Input → Plan → Loop(Tool calls) → Memory → Output. This is what we're building!

from langchain_openai import ChatOpenAI from langchain_core.messages import HumanMessage, SystemMessage llm = ChatOpenAI(model="gpt-4o", temperature=0) # Simple call — like chatting directly print(llm.invoke("What is an AI agent?").content) # Multi-turn: give it a persona + user message msgs = [SystemMessage("You are a helpful coding assistant."), HumanMessage("Explain LangGraph in simple words.")] print(llm.invoke(msgs).content) # Streaming — see tokens appear one by one (great for UX!) for chunk in llm.stream("Explain tool calling in 3 bullet points"): print(chunk.content, end="", flush=True)
🟣 Why temperature=0?

Temperature controls creativity. 0 = deterministic (same question, same answer every time — great for agents that need reliable tool decisions). Higher values = more creative but less predictable.

from langchain_core.tools import tool from langchain_community.tools import DuckDuckGoSearchRun @tool # ← This decorator tells LangChain "this is an agent tool!" def get_weather(city: str) -> str: """Get current weather for a city. Use when user asks about weather.""" return f"Weather in {city}: 22°C, Sunny ☀️ (mock data)" @tool def calculate(expression: str) -> str: """Safely evaluate a math expression like '42*17' or '100/4'.""" try: return str(eval(expression)) except: return "Error: invalid expression" search = DuckDuckGoSearchRun() # Free web search — no API key needed! tools = [get_weather, calculate, search]
💡 The docstring IS the tool description!

The LLM reads your """docstring""" to decide WHEN to call the tool. Write it like instructions for someone who doesn't know Python — clear, specific, with examples of when to use it!

from langchain_openai import OpenAIEmbeddings from langchain_community.vectorstores import FAISS from langgraph.checkpoint.memory import MemorySaver # LONG-TERM: Convert text to vectors, store in FAISS emb = OpenAIEmbeddings(model="text-embedding-3-small") vs = FAISS.from_texts(["Our refund policy is 30 days.", "Support: help@company.com"], emb) # Semantic search — finds relevant text even with different words! docs = vs.similarity_search("How do I get my money back?", k=2) print(docs[0].page_content) # → "Our refund policy is 30 days." # SHORT-TERM: MemorySaver keeps conversation history per user memory = MemorySaver() # pass to agent: create_react_agent(..., checkpointer=memory)
🟣 Why Vectors?

Regular search finds exact words. Vector search finds meaning. "How do I get my money back?" matches "Our refund policy is 30 days." — even though no words overlap. This is what makes RAG so powerful!

from langchain_community.document_loaders import PyPDFLoader from langchain_text_splitters import RecursiveCharacterTextSplitter from langchain.tools.retriever import create_retriever_tool # Step 1: Load your PDF knowledge base docs = PyPDFLoader("company-docs.pdf").load() # Step 2: Split into overlapping chunks (overlap prevents cut-off context) chunks = RecursiveCharacterTextSplitter(chunk_size=512, chunk_overlap=64).split_documents(docs) # Step 3: Embed all chunks and store in FAISS vs = FAISS.from_documents(chunks, OpenAIEmbeddings()) retriever = vs.as_retriever(search_kwargs={"k":4}) # Step 4: Wrap as a tool — the agent will call this automatically! rag_tool = create_retriever_tool(retriever, name="search_docs", description="Search internal company documents for policies, FAQs, procedures.") tools = [rag_tool, search, get_weather, calculate] # full toolkit!
📏 chunk_size=512, chunk_overlap=64 — Why?

Too big = irrelevant text dilutes the answer. Too small = loses context. 512 tokens ≈ one paragraph. The 64-token overlap ensures sentences that span chunk boundaries aren't cut in half!

✅ CH 6 DONE
  • PDF → chunks → FAISS is the standard RAG pipeline
  • create_retriever_tool wraps it as an agent tool
  • Agent now autonomously picks: search_docs vs web_search vs calculate

It runs a state machine: Think (call LLM) → Route (tool call? or done?) → Execute tool → Update state → back to Think. The thread_id lets it resume a conversation after days apart!

from langgraph.graph import StateGraph, END from typing import TypedDict class State(TypedDict): messages: list # shared state passed between agents # Three specialist agents — each with their own tools researcher = create_react_agent(llm, [search, rag_tool]) writer = create_react_agent(llm, []) # writer just thinks critic = create_react_agent(llm, []) # critic just reviews # Build the workflow graph g = StateGraph(State) g.add_node("researcher", lambda s: researcher.invoke(s)) g.add_node("writer", lambda s: writer.invoke(s)) g.add_node("critic", lambda s: critic.invoke(s)) g.add_edge("researcher", "writer") # research → write → review → done g.add_edge("writer", "critic") g.add_edge("critic", END) g.set_entry_point("researcher") crew = g.compile() # ready to run!
✅ CH 8 DONE

  • Edges define the pipeline: who passes to whom

using Microsoft.SemanticKernel; public class ToolPlugin { /// <summary>Get current weather for a city.</summary> [KernelFunction, Description("Get weather info for a city")] public string GetWeather([Description("City name")] string city) => $"Weather in {city}: 22°C, Sunny ☀️ (mock)"; /// <summary>Evaluate a math expression safely.</summary> [KernelFunction, Description("Calculate a math expression like '42*17'")] public string Calculate([Description("Math expression")] string expression) { try { return DataTable.Compute(expression).ToString()!; } catch { return "Error: invalid expression"; } } } // Register plugin with the kernel kernel.Plugins.AddFromType<ToolPlugin>("tools");
💡 [Description] IS the tool prompt

The Description attribute text is sent to the LLM as the tool description. Be specific! Bad: "Calculate something". Good: "Evaluate a math expression like '42*17' or '100/4+2'". The LLM reads this to decide when to call your function.
